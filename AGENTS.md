# AGENTS.md
- Public repo hygiene: no secret values in the repo (names only in README/.env.example); full PayPal payloads are not stored; audit/rate-limit logs expire after 90 days via pg_cron; users self-delete via `deleteMyData` — required for open-sourcing the code.
- Model tiering: main analysis uses Nemotron Super; translation tries Nemotron Nano first and falls back to Super on error or untranslated output — faster/cheaper while keeping quality.
- `analyze-dispute` saves analysis rows with the admin client after verifying ownership, because report columns are not selectable by browsers; each saved source records its provider (tavily / tavily_extract / official; legacy bright_data rows still display). Platform and official law pages are read with Tavily Extract from an allowlist — one search vendor, one key.
- Dispute analysis AI runs on Nebius Token Factory (OpenAI-compatible) with an NVIDIA Nemotron model, key `NEBIUS_API_KEY`, in `supabase/functions/analyze-dispute` — required by the Nebius × NVIDIA hackathon rules.
- Each analysis run produces one English master row; other report languages are translation rows (`parent_analysis_id`) that must keep the master's verdict, confidence and argument count — keeps EN/ZH results consistent.
- Full report content (recommendation, arguments, email, sources) is served only via `getAnalysisReport` server fn, redacted until `disputes.paid`; browsers cannot select those columns and only service_role can set `paid` — keeps the paywall server-enforced.
- Special unlock code is checked only server-side (`redeemSpecialCode`, secret `SPECIAL_UNLOCK_CODE`, limits in `special_code_settings` via atomic `redeem_special_code`) and sets the same `disputes.paid` flag as PayPal — one unlock path for the report.
- Case progress lives in `disputes.case_status` (validated by trigger) plus append-only `dispute_events`; `disputes.status` stays reserved for AI analysis state — keeps tracking separate from the analysis pipeline. Rules in `src/lib/case-status.ts`.
- UI locales are EN/ZH (in `i18n.ts`) and NL (`locales/nl.json`); feature strings added later go in `locales/extra.ts` for all three — one place to keep languages in sync.
- Human-help requests go to `expert_help_requests` only via the `submitHelpRequest` server fn (optional sign-in, case ownership checked, per-email daily cap); no public contact email is shown — keeps the owner's address private.
